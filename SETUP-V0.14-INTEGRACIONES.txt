- fila_cero_delivery_queue

- funciones privadas para el dispatcher

No toca optica_*, hipso_*, yorka_*, devweb_*, donato_*, etc.

  VAPID_SUBJECT=mailto:martinub250@gmail.com

5. CRON PARA ENVIAR PUSH / EMAIL / WHATSAPP Y LIBERAR PAGOS VENCIDOS
===============================================================================

Crea un secreto aleatorio largo, por ejemplo de 40+ caracteres, y guárdalo en:

Supabase -> Edge Functions -> Secrets

  FILA_CERO_CRON_SECRET=<tu secreto aleatorio>

Luego ve a Supabase -> Integrations / Cron / Jobs (el nombre puede variar) y crea:

  Nombre: fila-cero-dispatch-v014
  Frecuencia: cada 1 minuto
  Tipo: HTTP request / Edge Function
  Método: POST
  URL:
  https://kxldsjodgfonrrlwjbws.supabase.co/functions/v1/fila-cero-dispatch

Header adicional:
  x-fila-cero-cron: <EL MISMO FILA_CERO_CRON_SECRET>

Este job procesa exclusivamente fila_cero_delivery_queue y también libera holds
de abonos vencidos. No ejecuta lógica de otras aplicaciones.

6. EMAIL — RESEND
===============================================================================

La v0.14 está preparada para Resend.

Crea una cuenta/proyecto en Resend y un API key.
Para producción conviene verificar un dominio propio de Fila Cero.

En Supabase -> Edge Functions -> Secrets agrega:

  RESEND_API_KEY=<tu clave Resend>
  RESEND_FROM=Fila Cero <reservas@TU-DOMINIO.cl>

El dispatcher enviará recordatorios, si el usuario los seleccionó:
- 24 horas antes
- 2 horas antes

Si Resend no está configurado, el resto de Fila Cero sigue funcionando.

===============================================================================
7. WHATSAPP — META WHATSAPP BUSINESS PLATFORM
===============================================================================

Debes tener una cuenta de WhatsApp Business Platform / Cloud API y una plantilla
aprobada para recordatorios iniciados por la empresa.

La plantilla que espera esta versión usa 4 variables de cuerpo, en este orden:
  1) nombre del cliente
  2) servicio
  3) fecha y hora
  4) nombre del centro/profesional

En Supabase -> Edge Functions -> Secrets agrega:

  WHATSAPP_MESSAGES_URL=<URL completa .../PHONE_NUMBER_ID/messages>
  WHATSAPP_ACCESS_TOKEN=<token servidor Meta>
  WHATSAPP_TEMPLATE_REMINDER=<nombre de la plantilla aprobada>
  WHATSAPP_TEMPLATE_LANGUAGE=es_CL

El cliente decide si desea recordatorio por WhatsApp al reservar.

8. GOOGLE CALENDAR
===============================================================================

Esta versión NO pide acceso de escritura permanente al calendario del usuario.
Después de confirmar una reserva aparecen:

  - Agregar a Google Calendar
  - Descargar calendario (.ics)

También aparecen en Mi cuenta -> Historial para reservas confirmadas.

Ventaja: no necesitas agregar nuevos scopes OAuth de Google Calendar ni almacenar
refresh tokens. El usuario confirma el evento directamente en Google Calendar.

Si más adelante quieres sincronización automática/bidireccional, esa sería una
fase distinta que requiere OAuth Calendar y manejo seguro de tokens.

9. MERCADO PAGO — ABONO PARA ASEGURAR LA HORA
===============================================================================

La empresa puede marcar al publicar una hora:
  "Solicitar abono para asegurar la reserva"

y definir el monto.

Al reservar:
1) Fila Cero retiene la hora por 15 minutos.
2) El backend crea una preferencia Checkout Pro.
3) La persona paga en Mercado Pago.
4) El webhook consulta el pago directamente en la API de Mercado Pago.
5) Si queda aprobado, la reserva pasa a CONFIRMED.
6) Si falla/cancela, el cupo vuelve a estar disponible.

Crea una aplicación de Mercado Pago y obtén el Access Token de PRODUCCIÓN.

En Supabase -> Edge Functions -> Secrets agrega:

  MERCADOPAGO_ACCESS_TOKEN=<ACCESS TOKEN>
  FILA_CERO_APP_URL=https://fila-cero.concepcion.workers.dev/

En Mercado Pago -> Tus integraciones -> Webhooks configura el evento PAGOS:

  https://kxldsjodgfonrrlwjbws.supabase.co/functions/v1/fila-cero-mercadopago-webhook

Después utiliza el simulador de Webhooks de Mercado Pago para comprobar que la
URL responde correctamente.

MUY IMPORTANTE SOBRE EL MODELO DE PAGOS
---------------------------------------
Esta v0.14 usa UNA cuenta de Mercado Pago: la cuenta cuyo Access Token configures.
Por lo tanto, los abonos llegan a esa cuenta.

No implementa todavía reparto automático del dinero a cada clínica/profesional.
Un marketplace multi-vendedor real requiere onboarding y liquidación por vendedor
con una integración/contrato específico del proveedor de pagos.

Antes de cobrar abonos a escala real, define claramente:
- quién recibe legalmente el dinero;
- cuándo se devuelve un abono;
- qué ocurre si el centro cancela;
- comisiones de Fila Cero;
- condiciones comerciales y tributarias.
